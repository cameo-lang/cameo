Coming from Ruby

Everything cameo accepts parses as Ruby, and where cameo accepts a construct it behaves as CRuby 3.4 does. The differences are below, each with the Ruby you would write and the cameo way.

  1. The same as in Ruby
  2. Values are immutable
  3. Typed fields instead of instance variables
  4. What the checker rejects
  5. Missing builtins
  6. Only in cameo: with, async, await and promises, protobuf

cameo differs from Ruby in three ways. A construct has a different meaning, almost always because values are immutable. The checker rejects a construct before the script runs, and names what to write instead. Or a builtin is missing, which raises an exception, mostly NameError or NoMethodError, when the script reaches it. The full list is doc/cameo-vs-ruby.md.

The same as in Ruby

  • Literals: nil, booleans, integers of any size, floats, strings with interpolation and heredocs, symbols, arrays, hashes, ranges, regular expressions, %w[] and %i[].
  • Control flow: if, unless, modifiers, case/when, pattern matching with case/in, while, until, loop, break with a value, next, &..
  • Methods and blocks: positional, optional, rest, keyword and block parameters; endless def; argument forwarding; yield; lambdas, procs, &:sym, numbered parameters.
  • Classes and modules: single inheritance and super; modules as namespaces and mixins through include and extend; Comparable, Enumerable, method_missing.
  • Exceptions: begin/rescue/else/ensure, raise, retry, and Ruby's exception classes.
  • The core classes: Integer, Float, String, Symbol, Array, Hash, Set, Range, Regexp, MatchData, Time, Math, Enumerator and lazy, with most of their methods; format, pack, rand.
  • The built-in libraries: require of set, time, pp, pathname, cgi, json and benchmark.

  end
end

shapes = [{ kind: :circle, r: 1.5 }, { kind: :square, side: 3 }, [4, 5]]

p words.tally.max_by { _2 }

  puts "done"

Of the 1318 cases in CRuby's benchmark suite that cameo may carry, 824 run under cameo with Ruby's output. What stops most of the rest is metaprogramming, instance variables, attr_* accessors and mutation of something other than a local variable, which the sections below cover.

Values are immutable

Nothing changes in place. A call that changes its receiver in Ruby (<<, push, delete, merge!, any bang method) rebinds the local variable it is called on to the changed copy. Another variable that held the old value keeps it.

Ruby

a = [1, 2]
b = a
a << 3
p a, b
[1, 2, 3]
[1, 2, 3]

cameo

a = [1, 2]
b = a
a << 3
p a, b
[1, 2, 3]
[1, 2]

The call returns what it returns in Ruby: the receiver for most, the removed element for pop, shift and delete. h[k] = v and a.x = 1 rebind the local the same way.

Such a call needs a local variable to rebind. On anything else, an element, a constant or a call's result, the checker rejects it: write the non-mutating form and assign the result.

Ruby

config = { tags: ["a"] }
config[:tags] << "b"
p config[:tags]
["a", "b"]

cameo

config = { tags: ["a"] }
config[:tags] << "b"
p config[:tags]
script.cameo:2: << changes its receiver, which cameo rebinds only for a local variable or a field in initialize; use + or append
config = { tags: ["a"] }
config[:tags] += ["b"]
p config[:tags]
["a", "b"]

Equality is structural: two arrays, hashes or instances with equal contents are == and hash alike. There is no object identity, so equal? and object_id do not exist. frozen? is true for every value, and freeze and dup change nothing.

Typed fields instead of instance variables

A class declares its fields with their types. Each field gets a reader. There are no instance variables and no setters: initialize is the one place a field is set, with self.x = v, and with makes a changed copy everywhere else.

Ruby

class Counter
  attr_reader :count

  def initialize
    @count = 0
  end

  def increment
    @count += 1
    self
  end
end

c = Counter.new
c.increment.increment
p c.count
2

cameo

class Counter
  int :count, default: 0

  def increment = with(count: count + 1)
end

c = Counter.new
c = c.increment.increment
p c.count
2

A field's type is one of proto3's scalar types (int32, uint64, double, bool, string, bytes and the rest), int and float for Ruby's Integer and Float, bignum for an Integer of any size, or list, set, map, ref and enum. A value of the wrong type raises TypeError, and one out of range RangeError. A class without initialize takes its fields as keywords.

class Point
  int32 :x, :y
  string :label, default: ""
end

pt = Point.new(x: 1, y: 2)
p pt
p pt == Point.new(x: 1, y: 2, label: "")

begin
  Point.new(x: "one")
rescue TypeError => e
  puts e.message
end
Point(x: 1, y: 2, label: "")
true
field x of Point takes an int32, not an instance of String

Assignment through a chain of readers that starts at a local variable is a copy too: line.to.x = 30 rebinds line to a copy whose to is a copy with x set.

class Point
  int :x, :y
end

class Line
  ref :from, Point
  ref :to, Point
end

line = Line.new(from: Point.new(x: 0, y: 0), to: Point.new(x: 3, y: 4))
before = line
line.to.x = 30
p line.to, before.to
Point(x: 30, y: 4)
Point(x: 3, y: 4)

A class is a value bound to its name. Evaluating the same class X … end again gives the same class; a different body reopens a copy of the class and rebinds X to it. Instances made before, and classes that inherit from it, keep the class as it was and do not see what the reopening adds. A builtin class cannot be reopened.

Missing builtins

These do not exist in cameo. A script that uses one fails when it reaches it, mostly with NameError or NoMethodError, and for a library with LoadError.

  • Left out by design: Struct and Data (classes declare typed fields), Rational and Complex, Marshal (instances are protobuf messages), ObjectSpace, GC, ENV, Module.new, refinements, binding, method, Proc#curry.
  • No I/O beyond standard output and error: File beyond its path methods (basename, dirname, extname, join and split), IO, Dir, gets, STDIN, STDOUT, STDERR.
  • No threads or processes: Thread, Fiber, Mutex, sleep, system, exec, spawn. cameo has async and await instead.
  • Not there yet: exit, at_exit, catch and throw, redo, printf (format exists), __method__, __LINE__, Enumerator.new, Integer() with a base, Random as a class (rand and srand exist), autoload.
  • Libraries: require of anything but set, time, pp, pathname, cgi, json and benchmark, such as yaml.

Only in cameo

with

value.with(field: v) returns a copy with the named fields replaced; it is Ruby's Data#with. With a block, the block gets the value and returns a hash of the changes. On a Hash, with merges.

class Point
  int :x, :y
end

pt = Point.new(x: 1, y: 2)
p pt.with(x: 10)
p pt.with { |q| { y: q.y * 5 } }
p pt
p({ a: 1 }.with(b: 2))
Point(x: 10, y: 2)
Point(x: 1, y: 10)
Point(x: 1, y: 2)
{a: 1, b: 2}

async, await and promises

The async guide explains the model, shows it on one core, and walks through every example.

Concurrency comes from the Cameo module, which a script includes: at the top level for every method, or in a class body for that class. Without it async and await are unknown; Cameo.async and Cameo.await work without it.

async receiver, :method, args… runs one method call on a goroutine of its own, over copies of the receiver and the arguments, and returns the call's promise at once: an Integer that names the result to come. await returns the result, or raises the exception the call raised. It takes a promise, a list of them, or :all, every call the current method started and has not awaited. A call shares no memory with the script that started it, so a Proc, a class or a block cannot be passed to one.

include Cameo

class Worker
  int :factor

  def times(n) = n * factor

  def boom(msg)
    raise ArgumentError, msg
  end
end

w = Worker.new(factor: 3)

job = async w, :times, 4       # starts w.times(4) on a goroutine
p job                          # the promise: an Integer
p await job

jobs = [1, 2, 3].map { |n| async w, :times, n }
p await(jobs)                  # every result, in order

async w, :times, 10
async w, :times, 20
p await :all                   # every call this scope started and did not await

begin
  await w, :boom, "no"         # async and await in one step
rescue ArgumentError => e
  puts "the call raised: #{e.message}"
end
1
12
[3, 6, 9]
[30, 60]
the call raised: no

Every core at once

Go spreads the workers over the CPUs, so calls that compute run in parallel. Each of these computes the 29th Fibonacci number the slow way:

# Fibonacci on every core. async starts each call on a worker of its own, a
# goroutine that Go spreads over the CPUs, and returns its promise at once;
# await takes the list of promises and returns the results in order. The
# four calls run at once, one per core when there are four.
include Cameo

class Fib
  def of(n) = n < 2 ? n : of(n - 1) + of(n - 2)
end

fib = Fib.new
promises = [29, 29, 29, 29].map { |n| async fib, :of, n }
p promises
p await(promises)
[1, 2, 3, 4]
[514229, 514229, 514229, 514229]

On a machine with four cores the four calls take 1.2 seconds, where running them one after another takes 2.3; time shows the cores at work, with more CPU time than wall time:

$ time cameo examples/fibonacci.cameo
[1, 2, 3, 4]
[514229, 514229, 514229, 514229]

Settling a promise by hand

promise makes a pending promise, which resolve promise, value settles with a value and fail promise, exception with an exception, from the script or from a worker it was passed to: a promise is an Integer, so it travels like any other value. fail takes what raise takes after the promise; with anything but a promise first it raises, as Ruby's fail does. A promise is settled once. A Go host settles promises the same way when it does I/O for a script; see promises in the host.

include Cameo

class Courier
  def deliver(promise, parcel) = resolve(promise, "#{parcel}, delivered")
  def lose(promise, parcel) = fail(promise, KeyError, "#{parcel} is lost")
end

courier = Courier.new
parcel = promise               # a pending promise, nobody's result yet
async courier, :deliver, parcel, "books"
p await(parcel)

missing = promise
async courier, :lose, missing, "a lamp"
begin
  await missing
rescue KeyError => e
  puts e.message
end

begin
  resolve parcel, "again"
rescue ArgumentError => e
  puts e.message
end
"books, delivered"
a lamp is lost
promise 1 is settled already

Protobuf

Every class is a protobuf message. A field's number is derived from a hash of its name, so it stays the same when fields are added, removed or reordered; number: gives one from 1 to 4096 instead, as in int :x, number: 1, which is shorter on the wire. reserved keeps a removed field's number and name out of use. to_proto returns the wire form, from_proto reads it back, and Point.proto returns the .proto text. cameo proto script.cameo writes the .proto files of every class a script defines.

class Point
  int :x, :y
end

pt = Point.new(x: 3, y: 4)
data = pt.to_proto
p data.bytesize
p Point.from_proto(data) == pt
puts Point.proto
8
true
message Point {
  optional int64 x = 64843;
  optional int64 y = 64608;
}

A Symbol becomes a String where a value leaves cameo, in a protobuf message or an async call, unless an enum field declares it.
