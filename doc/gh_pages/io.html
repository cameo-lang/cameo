Enabling I/O

A script does no I/O of its own. What it may read and write is decided by whoever runs it: a flag on the command line, or two calls in the Go program that embeds it.

  1. What a script can do by default
  2. On the command line: --io
  3. From a Go program: AllowIO and FileSystem
  4. Everything else: a module of Go functions

What a script can do by default

It computes, and it writes to the two streams its host gave it: puts, print, p and warn. It has no ENV, no sockets, no system and no backticks. File handles paths as strings, and its methods that touch a file do not exist; the error says how to get them.

p File.respond_to?(:read)
p File.basename("/home/ada/notes.txt")      # a path is only a string

begin
  File.read("notes.txt")
rescue NoMethodError => e
  puts e.message
end
false
"notes.txt"
undefined method 'read' for class File: the host allows no file I/O; run the script with cameo --io=file, or let the program say AllowIO("file") and give it a file system with FileSystem

So a script from an untrusted source can be run as it is: the worst it does is compute for too long, and RunContext stops that.

On the command line: --io

cameo --io script.cameo allows every kind of I/O, and cameo --io=file script.cameo the kinds named, separated by commas. The flag goes before the script, and before irb, resume and debug.

text = File.read("notes.txt")
puts text.lines.size
File.write("copy.txt", text.upcase)
File.open("copy.txt") { |f| puts f.gets }
cameo --io=file io.cameo
3

Without the flag the same script stops at its first line, with the message above, and exits with status 1.

From a Go program: AllowIO and FileSystem

A program that embeds cameo allows a kind with prog.AllowIO("file") and says which files with prog.FileSystem(fsys, dir). Both are needed. The file system is an afero Fs: the disk, one directory of it, a read-only view, or memory. prog.AllowHostIO("file") is the short form for the machine's own files from the working directory, which is what the command line does.

The example examples/io gives this script a file system in memory:

# The script reads and writes files as in Ruby. Which files those are is
# the Go program's choice.
text = File.read("notes.txt")
puts "#{text.lines.size} lines"
File.write("shout.txt", text.upcase)
File.open("shout.txt") { |f| puts f.gets }
// Command io lets a script read and write files, in a file system the Go
// program chooses. A script does no I/O unless the program that runs it
// allows a kind of it: here the kind "file", with a file system in
// memory that holds one file.
//
//	go run ./examples/io
package main

import (
	_ "embed"
	"fmt"
	"io"
	"os"

	"github.com/cameo-lang/cameo/src/cameo"
	"github.com/spf13/afero"
)

//go:embed notes.cameo
var script string

// run runs the script with the files of fsys, relative paths read from
// dir.
func run(fsys afero.Fs, dir string, stdout, stderr io.Writer) error {
	prog, err := cameo.Load("notes.cameo", script, stdout, stderr)
	if err != nil {
		return err
	}
	// Both are needed: the kind allowed, and a file system to read. The
	// file system may be the disk (afero.NewOsFs), one directory of it
	// (afero.NewBasePathFs), a read-only view (afero.NewReadOnlyFs) or
	// memory, as here.
	prog.AllowIO("file")
	prog.FileSystem(fsys, dir)
	return prog.Run()
}

func main() {
	fsys := afero.NewMemMapFs()
	if err := afero.WriteFile(fsys, "/work/notes.txt", []byte("three\nlines\nhere\n"), 0o644); err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}
	if err := run(fsys, "/work", os.Stdout, os.Stderr); err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}
	shout, _ := afero.ReadFile(fsys, "/work/shout.txt")
	fmt.Printf("the script wrote %d bytes into the file system\n", len(shout))
}
go run ./examples/io
3 lines
THREE
the script wrote 17 bytes into the file system

Given afero.NewReadOnlyFs(fsys) instead, the script reads the file and its File.write raises.

Everything else: a module of Go functions

Any other I/O, a database, an HTTP request, a queue, the script gets as a module the Go program defines: the program decides what the function does and what the script may ask of it. A function that takes time returns a promise, and the script awaits it while its other work goes on.

  • Native code shows a module of Go functions.
  • Embedding in Go has a program that fetches web pages for a script, each request on its own goroutine.
  • gRPC calls a public service the same way.
