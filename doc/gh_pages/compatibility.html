Compatibility

How much of ruby/spec, the specification of the Ruby language and its core and standard libraries, cameo passes, and why it does not pass the rest.

  • ruby/spec at commit 47b10f1d7b1c29bda01d6903cceddd5b0b4c857d
  • CRuby 3.3.6 (x86_64-linux), which runs every program as well
  • run on 2026-11-15
  • regenerate with make spec-status, which needs a Ruby with Prism and the copy of ruby/spec that make ruby-spec makes: it runs specs/run.rb, which writes specs/status.tsv, and then specs/compatibility.rb, which writes this page

specs/run.rb rewrites each spec file's mspec idioms into calls of a prelude and runs it under cameo and under CRuby. Each example has one status:

StatusMeans
passpasses under cameo, as under CRuby
not expectedstopped by something cameo leaves out on purpose; the reasons say what
bugCRuby passes it and cameo does not, for no reason cameo states: cameo should pass it
harnessCRuby does not pass it in this harness either, or it needs before, after or a shared example, which the prelude does not run

Only an example CRuby passes in this harness counts as one cameo should match. CRuby's own failures, mostly examples that need a part of mspec the prelude lacks (mock, should_receive, ruby_exe), and the examples CRuby does not run, which ruby/spec guards for a newer Ruby than CRuby 3.3.6, count as harness. Should match below is pass, not expected and bug together.

A spec file that did not run has no examples here. It counts once, under files not run, with what stopped it: cameo check refused it (check), it stopped before its first example (crash), it ran out of time (timeout), or Prism could not parse it for the rewrite (rewrite). specs/runner/classify.rb gives a status and a reason from the message that stopped an example or a file.
