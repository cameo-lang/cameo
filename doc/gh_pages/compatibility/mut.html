Compatibility › mut

mut — mutation

Every value is immutable. No call changes its receiver: a bang method of Ruby's core is refused before the script runs, and a mutator such as << or push raises when it runs.

What cameo refuses

The checker refuses sort!, map! and every other bang method of Ruby's core, setters, self.x = v outside initialize and nested multiple assignment. A mutator the checker cannot see, because it depends on the receiver, raises a CameoError that names the form to use.

names = ["carol", "alice", "bob"]
names.sort!
script.cameo:2: This is not supported, use names = names.sort instead (see https://15b.it/mut)
names = ["carol", "alice"]
other = names
names << "bob"
script.cameo:3: cameo does not support mutating calls without rebinding; use a = a << 1, +, or append (CameoError)

Why

A value that never changes can be shared without care: an async worker on another goroutine gets the same value as the script, a dump holds each value once, and a value a method returned stays what it was. In Ruby, other = names; names << "bob" changes other too; in cameo, nothing changes behind a variable's back.

A call that looked like Ruby's but rebound its receiver would read as Ruby and do something else, so cameo refuses it instead.

What to write instead

Assign the copy. a = a.sort, a += [x], h[k] = v and pt.x = 1 rebind the local to a copy with the change; another variable that held the old value keeps it.

names = ["carol", "alice"]
other = names
names += ["bob"]
names = names.sort
p names
p other
["alice", "bob", "carol"]
["carol", "alice"]

The rule: cameo and Ruby, different in cameo. Every code, and how many examples of ruby/spec each stops.
