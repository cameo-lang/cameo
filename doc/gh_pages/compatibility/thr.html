thr — threads

cameo has no Thread, Mutex, Queue, Fiber or Ractor. It has async, which runs a method of a value on a worker, and await, which collects the result.

What cameo refuses

The classes are absent, so a script fails when it reaches one.

t = Thread.new { 1 + 1 }
p t.value
script.cameo:1: uninitialized constant Thread (NameError)

Why

Threads share state that changes, and need locks to do it safely. cameo has no state that changes, so a worker can run on its own goroutine with a copy of the values it was given and nothing to lock. A promise is an Integer, which a worker, the script or the Go host settles, so a run that waits for one can pause, and its dump resumes with the promise still pending.

What to write instead

include Cameo, then async obj, :method, args returns a promise, and await returns its value or raises its error; see Async.

include Cameo

class Square
  def run(n) = n * n
end

job = Square.new
promises = (1..4).map { |n| async job, :run, n }
p promises.map { |pr| await pr }
[1, 4, 9, 16]
