Compatibility › bin

bin — binary strings

A binary String has bytes and no characters, and a UTF-8 String with characters beyond ASCII has no bytes alone.

What cameo refuses

A method that reads characters raises Encoding::CompatibilityError for a binary String, and getbyte raises for a UTF-8 String with characters beyond ASCII.

p b"\xFF\x41".upcase
script.cameo:1: upcase reads characters, and a binary string has bytes alone: say what they are with force_encoding first (see https://15b.it/bin) (Encoding::CompatibilityError)
p "é".getbyte(0)
script.cameo:1: getbyte reads a byte, and this UTF-8 string has characters beyond ASCII: call b first for its bytes, or read a character with [] (see https://15b.it/bin) (Encoding::CompatibilityError)

Why

Ruby reads a binary String's bytes as ASCII, and a UTF-8 String's bytes one by one, so a method can return part of a character or treat bytes as letters they are not. In cameo a String is text or bytes (inv), and a method that would mix them says so. The call that says which is meant is short.

What to write instead

Read bytes with bytes or getbyte on a binary String; b gives a String's bytes, and force_encoding("UTF-8") says that bytes are text.

p b"\xFF\x41".bytes
p "é".bytes
p "é".b.getbyte(0)
