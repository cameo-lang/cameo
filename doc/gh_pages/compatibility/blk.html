blk — blocks capture values

A block captures the values its variables have when it is made, not the variables. It cannot rebind a variable of the scope around it.

What cameo refuses

An assignment inside a block to a variable of the scope around it is refused before the script runs, as is a block that reads a name bound after it, other than the lambda assigned to that name.

total = 0
[1, 2, 3].each { |n| total += n }
p total
script.cameo:2: a block cannot rebind total, a variable of the scope around it: a block captures the values its variables have when it is made; bind a new name, or use reduce, each_with_object or while (see https://15b.it/blk)

Why

Ruby's block shares its scope's variables, a reference to state that changes, which nothing else in cameo is. A block that copies its values can go to a worker or into a dump as it is. The checker refuses the rebinding so that the accumulation idiom fails before the script runs, instead of doing nothing or looping forever.

What to write instead

Return the value instead of collecting it: sum, reduce, each_with_object, map or count, or a while loop, whose body shares the scope.

p [1, 2, 3].sum
p [1, 2, 3].reduce(0) { |total, n| total + n }
counts = %w[a b a].each_with_object(Hash.new(0)) { |w, h| h[w] += 1 }
p counts
