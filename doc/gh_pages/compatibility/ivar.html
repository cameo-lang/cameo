ivar — instance variables

cameo has no instance variables. A class declares its fields, with a type each, and an instance is a value whose fields never change.

What cameo refuses

The checker refuses @x, read or assigned, anywhere in a script, and names the field that takes its place.

class Counter
  def initialize
    @count = 0
  end

  def increment
    @count += 1
  end
end
script.cameo:3: @count = …: cameo has no instance variables; initialize sets a field with self.count = … (see https://15b.it/ivar)
script.cameo:7: @count = …: cameo has no instance variables; initialize sets a field with self.count = … (see https://15b.it/ivar)

Why

Every cameo object is a protobuf message: its fields are declared, typed and numbered, so an instance can be written into a dump when the script pauses, sent to an async worker, or handed to a Go host, and read back as the same value. An instance variable that any method may create, with any value, has no place in such a message.

The fields never change after initialize, so a value read from an object stays what it was. A changed object is a copy, which with makes.

What to write instead

Declare each field with its type. initialize sets a field with self.x = v, a method reads it as x, and with returns a copy with fields changed. A class without initialize takes its fields as keywords.

class Counter
  int :count, default: 0

  def increment
    with(count: count + 1)
  end
end

c = Counter.new.increment.increment
p c.count
2
