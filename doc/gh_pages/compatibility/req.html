req — libraries

A script is one file, and its libraries are built into cameo. require_relative and load are refused, and require of a library cameo does not build in raises a LoadError.

What cameo refuses

require_relative and load are refused before the script runs; require fails when it runs, as in Ruby when a gem is missing.

require_relative "helper"
script.cameo:1: require_relative is not supported; use nothing: a script is one file (see https://15b.it/req)
require "socket"
script.cameo:1: cannot load such file -- socket (LoadError)

Why

A cameo program carries its script, not a directory: a Go host embeds the source, and a dump of a paused run holds the code it resumes. Reading other files at run time would make a run depend on what lies next to it on the disk where it started. The libraries cameo builds in are written for it, without the I/O, threads and mutation it leaves out; stdlib.md lists them, with those planned and those left out.

What to write instead

Put the code in the script, or ask the host for a module. require takes the libraries cameo builds in.

require "json"
p JSON.parse('{"a": [1, 2]}')
{"a" => [1, 2]}
