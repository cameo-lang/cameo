meta — metaprogramming

cameo leaves out the parts of Ruby that write or change code while the script runs: eval, instance_eval, class_eval, define_method, undef, singleton classes and methods on one object.

What cameo refuses

The checker refuses each by name. send stays: it calls a method by its name, and refuses send(:initialize), which only new runs.

class Greeter
  %w[hello goodbye].each do |word|
    define_method(word) { |name| "#{word}, #{name}" }
  end
end
script.cameo:3: define_method is not supported; use def (see https://15b.it/meta)
p eval("1 + 2")
script.cameo:1: eval is not supported; use nothing (see https://15b.it/meta)

Why

A cameo script is checked before it runs, and pauses into a dump that another process resumes. Both need the code to be the code the file says: the checker can only refuse what it can see, and a resumed run finds every method where the script defined it. Code made from strings, or methods added to a class from a block, would be neither checked nor written into the dump.

A class is a value bound to its name, built in its body and sealed when the body ends, so no later call adds a method to it.

What to write instead

Write each method with def. When a method is chosen from data, send calls it by name, or a Hash maps the names to lambdas.

class Greeter
  WORDS = %w[hello goodbye]

  def greet(word, name)
    raise ArgumentError, "no word #{word}" unless WORDS.include?(word)
    "#{word}, #{name}"
  end
end

g = Greeter.new
puts g.greet("hello", "Ada")
puts g.send(:greet, "goodbye", "Ada")
hello, Ada
goodbye, Ada
