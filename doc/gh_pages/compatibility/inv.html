inv — invalid strings

A UTF-8 String holds whole characters, and none is invalid. Bytes that are not UTF-8 are a binary String, written b"...", and what makes text refuses them.

What cameo refuses

A string literal with bytes that are not UTF-8 is refused before the script runs. What would make such a String later, force_encoding("UTF-8") or JSON.parse of a lone surrogate, raises.

data = "\xFF\xFE"
script.cameo:1: a string literal with bytes that are not UTF-8 is a binary string and is written b"..." (see https://15b.it/inv)

Why

In Ruby a String can hold bytes that are not characters of its encoding, and every method that reads characters has to decide what to do with them, quietly or not. In cameo a String's encoding is a promise: a UTF-8 String is text a reader can read, and a binary String is bytes. A Go host gets text as a Go string and bytes as a []byte, and a protobuf string field, which must be UTF-8, can always hold a cameo String.

What to write instead

Write bytes as a binary string literal, b"\xFF\xFE", which takes the escapes "..." takes. Ruby reads it as a call of b on the string, so the same file runs on both.

data = b"\xFF\xFE"
p data.bytes
p data.encoding
[255, 254]
#<Encoding:BINARY (ASCII-8BIT)>
