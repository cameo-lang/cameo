## Objective
Floats in compiled methods: literals, locals, arithmetic with Integers,
comparisons, to_f and to_i, and Float results, with parameters still
Integers, so that numeric loops compile.

## Progress
- [x] A Float type in the checker; the result type of a method settled in rounds, with an unknown type for a call of a method not yet typed
- [x] The checker records every expression's type; the generator reads them instead of retyping
- [x] Generator: float64 in both twins, Integer operands converted, Integer against Float through object.CompareNumbers, fmod, toInt and bigToInt helpers
- [x] Tests: checker reasons, generator output, examples/aot/floats.rb held to Ruby's output
- [x] Conformance 61 same; make check; tests/performance/04-floats timed

## Obstacles
- **Issue:** `conversions[name] != 0` took to_i for unknown: tInt is the zero typ.
  **Resolution:** A presence check.
- **Issue:** The first floats example summed 1.upto(2**63), which does not end; Ruby had to be killed.
  **Resolution:** ratio(2**64, 3) exercises the twin with a Float result instead.
- **Issue:** mandelbrot first set `t` inside its while, which the checker leaves: nil on the path that skips the loop.
  **Resolution:** The script declares `t = 0.0` before the loop; the README says why.
- **Issue:** Ruby raises ZeroDivisionError for `-7.5 % 0`, an Integer zero, where cameo's interpreter gives NaN. The compiled code follows the interpreter, which is what the conformance suite holds it to.
  **Resolution:** Left out of the example; noted for the interpreter.

## Outcome
Numeric methods compile: mandelbrot 0.019 s compiled against 0.272 s on
YJIT and 2.517 s interpreted; pi 0.023 s against 0.434 s and 1.960 s.

## Insights
Typing in rounds with an unknown that joins with anything settles mutual
recursion without an order; a method typed Integer in one round and Float
in the next is a method that returns both, and is rightly left.
