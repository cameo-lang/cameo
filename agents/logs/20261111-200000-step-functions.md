## Objective
Step 22 of `doc/design/ir.md`: a builtin that calls its block can be
written so that what it keeps between two calls is values, and a run then
pauses inside its block and resumes there.

## Progress
- [x] `object/step.go`: `Stepper`, `Call`, `Got`, `Step`, `DefineStep`,
      `DefineStepFunction`; a stepper is a `NativeFn` for Go callers too
- [x] `eval`: an activation of kind `actStep`; `stepOn` runs a step and
      pushes the block's activation
- [x] `Integer#times`, `upto`, `downto` and `loop` are steppers
- [x] The dump holds a builtin's activation (`Dump.Builtin`), and the
      resume finds the stepper by class and name
- [x] Tests: a run pauses and resumes inside the blocks of all four,
      nested, with a `break`, a `StopIteration`, integers past 64 bits;
      the number of loops inside a stepper's block is one
- [x] `doc/design/pause.md`, `doc/design/ir.md`

## Obstacles
- **Issue:** `loop` ends when its block raises `StopIteration`, and a
  step saw only the block's value.
  **Resolution:** `Step.Rescue` asks for the exception, which comes back
  in `Got.Raised`; the stepper ends the builtin or returns the exception
  to raise it again.
- **Issue:** The test helper removed the lines `Test.pause` for the run
  it compares with, and missed a `Test.pause` written inside a block on
  one line, so that run paused too.
  **Resolution:** The comparison run keeps the script as it is and has a
  `Test.pause` that does nothing.
- **Issue:** A `loop` whose block captured a StringIO could not be
  dumped: the block cannot travel, so the builtin cannot go on. The dump
  fails, and the run, already stopped, is lost.
  **Resolution:** The dump refuses, which is right for the dump. That a
  run should go on when its dump fails is a follow-up: `Run` can
  continue from the frozen activations.

## Outcome
`n.times { … }`, `a.upto(b) { … }` and `loop { … }` no longer hold a
pause off. The next groups are List, Hash, Range and Set.
