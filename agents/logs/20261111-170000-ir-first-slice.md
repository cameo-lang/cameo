## Objective
Step 7 of `doc/design/ir.md`: a compiler from the AST to the IR and an
evaluator that runs the IR, for the first slice of the language, with the
tree walker running whatever does not compile yet.

## Obstacles
- **Issue:** A top-level `def` is a statement and, once it ran, a method's
  body, the same node. The cache of compiled code keyed on the node, so
  the statement's "does not compile" hid the method's IR.
  **Resolution:** The key says whether the node was compiled as a
  statement.
- **Issue:** An interpolated string converts each part with `to_s` before
  the next part is evaluated, and `yield` raises for a missing block
  before its arguments are evaluated. Operands on a stack are all
  evaluated first.
  **Resolution:** `INTERP` carries its parts as lists and converts
  between them; `NEED_BLOCK` comes before a `YIELD`'s arguments.
- **Issue:** `proc { |a, k: 1| }.call(1)` binds `k` to nil, and
  `proc { |a, b = 10, *rest, k:| }.arity` is -3, on `main` already. Both
  evaluators agree.
  **Resolution:** Unresolved and not part of this task; the tests avoid
  keyword parameters of a proc.

## Outcome
`make check` runs on the IR wherever a method, block or statement
compiles, and the example corpus also runs with the IR off. The next
slices add exceptions, `case`, patterns and definitions.

## Insights
Because both evaluators share scopes, frames and procs, the fallback
needs no boundary code: a block compiled to IR runs inside a method on
the tree walker and the other way round. The counts of what ran where
are what make a green run mean the IR was exercised.
