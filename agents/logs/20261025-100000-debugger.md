## Objective
`cameo debug script` runs a script under a debugger that behaves like
rdbg: step, next, finish, continue, breakpoints on lines and methods,
backtrace, info, list, up/down, expressions in a frame. `require "debug"`
with `debugger` or `binding.break` stops a plain run the same way.

## Progress
- [x] eval: compile becomes a method of the program's code, so a body
      compiled while the debugger is on carries a line hook per statement
- [x] eval: Debugger with its console, frames pushed by invoke, callBlock
      and class bodies, breakpoints, and expressions evaluated in a frame
      behind the prelude cameo irb introduced
- [x] eval: the "debug" library, debugger, binding.break
- [x] cameo: Program.Console, Debug, Quit
- [x] cmd: the debug command; a script's require "debug" talks on the

- [x] tests: Go tests through the host API and the command, one
      integration test; docs: README, doc/debugger.md

## Obstacles
- **Issue:** `next` at a class statement stepped into the class body.
  **Resolution:** A class body is a frame, as in Ruby.

## Outcome
`make check` green. The debugger does not reach async workers, and sees
only statements compiled after it was switched on; doc/debugger.md says
so.

## Insights
The closure compiler has no per-node hook, so the debugger hooks
statements at compile time behind a flag on the program's code. That is
cheap when off and reaches every body compiled from then on.
