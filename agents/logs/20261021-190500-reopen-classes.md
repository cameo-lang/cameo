# Task: reopen a class as Ruby does, on a copy, and bind its name before its body

**Started:** 2026-10-21 19:05:00
**Ended:** 2026-10-21 19:40:00
**Strategy:** Feature (TDD)
**Status:** Completed
**Complexity:** Simple
**Used Models:** Opus
**Token usage (Estimated):** 200k input, 25k output

## Objective
A second `class A` keeps what the first defined, as in Ruby: the body runs
on a copy of the class, and the copy replaces the class when the body ends.
A class body can call the class by its name.

## Progress
- [x] Tests: methods, fields and constants kept, super from both bodies,
  a field declared again, superclass mismatch, class against module, a
  module reopened, the name inside the body, a body that raises
- [x] object.Class.Copy, which moves the methods and fields to the copy
- [x] evalClassDef and evalModuleDef reopen; the name binds before the body
- [x] Design notes, cameo-vs-ruby, the site, examples/reopening.cameo
- [x] make check, pull request

## Obstacles
- **Issue:** examples/redefinition.cameo declares `string :name` in each
  body, which a reopened class already has.
  **Resolution:** A reopening body may declare a field again with the same
  type and default; any other declaration of it still fails.
- **Issue:** A copied method kept the old class as its owner, so super
  and constant lookup from it started at the old class.
  **Resolution:** Copy moves the methods and fields the class declared to
  the copy, and the class in their lexical chain.

## Outcome
Reopening works as in Ruby, except that instances made before and classes
that inherit from the reopened class keep the old class.

## Insights
A class body ran on a new class, so binding the name earlier and starting
from a copy were the whole change; the method owners and lexical chains
were what the copy had to move.
