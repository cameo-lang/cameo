## Objective
A dump holds nothing of the host, so spicy's card deck, which a host
module deals from, is lost on `spicy <dump>`. Let a host keep such an
object in the dump: the object gives its state as bytes when the dump is
written and takes them back on the resumed program.

## Decisions
- The API is `Program.Keep(name, Stateful)`, with
  `Stateful{Dehydrate() ([]byte, error); Rehydrate([]byte) error}`. The
  dump stores the bytes by name in `host_state`; cameo does not read
  them.
- Keep on a resumed program rehydrates at once; there is no separate
  restore step, so the same host code serves a fresh and a resumed
  program.
- Run, and Call and RunContext through it, refuse while the dump holds
  state no Keep claimed, naming it: a host that forgot an object hears of
  it instead of a script that goes on with an empty deck.
- A program that resumes and dumps again passes unclaimed state on.
- Released with cameo.Env (#460) as v0.6.0, as the owner chose.
