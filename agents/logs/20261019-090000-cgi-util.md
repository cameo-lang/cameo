## Objective
Bring `CGI` in line with Ruby 3.4's `cgi/escape` and `cgi/util` where no I/O
is involved: `escapeElement`, `unescapeElement`, `rfc1123_date`, `pretty`,
and Ruby's exact `unescapeHTML`.

## Progress
- [x] Probed Ruby 3.4.1 (benchmarks/warmruby) on escapes, entities, elements, dates and `pretty`
- [x] Fixed `unescapeHTML`: `&&amp;`, `&lt&lt;`, U+10FFFF and surrogates now match Ruby
- [x] Added `escapeElement`, `unescapeElement` and snake_case forms, `rfc1123_date`, `pretty`
- [x] examples/cgi.cameo with output generated by Ruby 3.4, unit tests, an integration test
- [x] Docs: cameo-vs-ruby.md, design, README

## Obstacles
- **Issue:** The `ruby` on PATH is 3.3.6.
  **Resolution:** Built benchmarks/warmruby, which runs CRuby 3.4.1, and compared against it.
- **Issue:** Ruby's `escapeElement` and `pretty` use lookaround, which cameo's regexps (RE2) lack.
  **Resolution:** Ported them as hand-written scans, including the backtracking of `(?!\n)` and of `(?:shift)*__`.
- **Issue:** First port read `\w` as Unicode; Ruby's `\w` is ASCII.
  **Resolution:** A comparison against Ruby on `<bé>` caught it.

## Outcome
`CGI` has every non-I/O function of `cgi/escape` and `cgi/util`, each checked
against Ruby 3.4's output. `CGI.escape(:sym)` still returns `"sym"` where Ruby
raises a TypeError, as every cameo String argument accepts a Symbol.
