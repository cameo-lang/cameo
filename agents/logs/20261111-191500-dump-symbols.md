# Task: a dump keeps symbols

**Started:** 2026-11-11 19:05:00
**Ended:** 2026-11-11 19:15:00
**Strategy:** Bug Fix
**Status:** Completed
**Complexity:** Simple
**Used Models:** Fable 5.2
**Token usage (Estimated):** 80k input, 6k output

## Objective
A symbol read back from a dump as a String, as it does wherever a value
crosses the envelope. A run that paused with `{k: 1}` in flight resumed
with `{"k" => 1}`, and `mode == :red` was false after a resume.

## Progress
- [x] A test that fails: symbols in a variable, as Hash keys, captured by
      a Proc and in a constant of a class, across a pause
- [x] `cameo.Value` has `symbol_value`; `protogen.Encoder.WithSymbols`
      writes it; every decoder reads it
- [x] `Interp.Dump` encodes with it
- [x] `doc/design/pause.md` and the open question in `doc/design/ir.md`

## Obstacles
- **Issue:** The rule that a symbol is a String in the envelope is the
  language's, for hosts and other programs, and the human had not said
  whether to change it.
  **Resolution:** The rule stays where it was made: `to_value_proto`,
  `async` and the host API write a string. Only the dump writes a
  symbol, which is read by the run that wrote it. Whether the others
  should follow is still asked in `doc/design/ir.md`.

## Outcome
A resumed run has its symbols. The test of the pull request below, which
avoided symbols across a pause, holds them again.
