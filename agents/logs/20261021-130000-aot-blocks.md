## Objective
The blocks step of doc/design/aot.md: times, upto and downto on an Integer
and each on a Range of Integers compile, with their block's body, so that
the loops most scripts are written with run as Go.

## Progress
- [x] Checker: a block scope that reads and sets the locals around it and owns the locals first set in it; break and next inside a loop or a block
- [x] Generator: a Go loop per block call, the counter its own, the bounds read once, a stop check per pass; the twin on *big.Int loops the same way
- [x] Tests: generator unit tests; examples/aot/blocks.rb held to Ruby's output compiled and interpreted
- [x] Conformance: 61 of 920 scripts compile a method, as before; none of CRuby's benchmarks loops with a block inside a top-level method
- [x] tests/performance/03-blocks timed on the Mac mini M1: times 3.209 s interpreted, 0.062 s compiled, YJIT 0.963 s; triples 1.688, 0.034, 0.278
- [x] make check, pull request

## Obstacles
- **Issue:** A `for` loop desugars to `k = nil` before the each, so `for` is not compiled: nil is not an Integer.
  **Resolution:** Left as is; `for` is rare in the scripts, and the message names the nil.
- **Issue:** The first loop header had an untyped `0` as the counter's start, which Go typed as int against an int64 bound.
  **Resolution:** Literals in a loop header are written as `int64(...)`.
- **Issue:** Go's `break` and `next` inside the inlined body mean what Ruby's mean only because each Ruby loop or block became exactly one Go loop; a body assigning the block's parameter would have moved a Go loop over the parameter.
  **Resolution:** The loop counts on a temporary of its own and copies it into the parameter at the top of the body.

## Outcome
times, upto, downto and each with a block compile to Go loops; examples/aot/blocks.rb and tests/performance/03-blocks show them.

## Insights
Blocks as inlined loops rather than closures: no closure is allocated, the
body sees the method's locals as Go locals, and return inside the block is
a Go return.
