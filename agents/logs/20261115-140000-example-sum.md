## Objective
An example app: the user types numbers, one a line, and it sums them up.
`^C` pauses the app and dumps it; cameo resumes it from the dump.

## Progress
- [x] examples/sum: sum.cameo and a Go program that embeds cameo
- [x] A test of a run to its end and of a pause while the script waits,
      resumed twice from one dump
- [x] Tried by hand in a pseudo-terminal: ^C, resume, ^C again, resume
- [x] README of the example, and the list in the README

## Obstacles
- **Issue:** A script reads no keyboard: `gets` and `STDIN` are absent,
  so the `cameo` command cannot run such a script.
  **Resolution:** A Go program embeds cameo and gives the script the
  module `Keyboard`, as examples/webfetch gives `Web`.
- **Issue:** A host method that blocks on the keyboard would keep a ^C
  from pausing until Enter: a run pauses once the builtin it is in
  returns.
  **Resolution:** `Keyboard.line` returns a promise, and the script
  awaits it. A run waiting in `await` pauses at once, and the dump holds
  the promise as pending.
- **Issue:** The resumed program must settle the promise the script
  waits for, and the cameo package has no call that lists the pending
  promises of a resumed program.
  **Resolution:** The program reads them from the dump's `promises`, the
  documented `cameo.Dump` message, and settles each with
  `PendingPromise(id)`.
- **Issue:** `Integer(text, exception: false)` raises in cameo, where
  Ruby returns nil.
  **Resolution:** The script rescues ArgumentError instead.

## Outcome
`go run ./examples/sum` sums lines until `^D`; `^C` writes the state to a
temporary file, and `go run ./examples/sum <file>` goes on from it.

## Insights
- Every promise of the run stays in the dump with its value, so the dump
  grows by one promise a line typed.
