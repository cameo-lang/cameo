## Objective
Steps 4 and 5 of `doc/design/ir.md`: `make proto` with pinned tools and a CI
check, then the envelope `cameo.Value` and the dump as `.proto` files with
committed generated code, in place of the descriptors built by hand over
`dynamicpb`. The IR's messages follow in the same package.

- [x] `make proto`: fetches protoc 33.0 into `bin/`, builds protoc-gen-go

- [x] `make proto-check`, and the CI step that runs it
- [x] `src/cameopb/cameo/value.proto`; the encoder and decoder on the

## Obstacles
- **Issue:** The message of an exception class is a dynamic message with
  fields of type `cameo.Value`, so the decoder meets a dynamic
  `cameo.Value` there, not the generated type.
  **Resolution:** `Decoder.reflected` reads such a message through its wire
  form. dynamicpb accepts the generated message when one is set, since it
  compares full names.
- **Issue:** A first test held the new encoder to bytes written by hand.
  The old encoder wrote a map entry's value before its key: dynamicpb fixes
  no field order.
  **Resolution:** The test reads bytes captured from the old encoder and
  holds the new one to reading back, not to an order of fields.
- **Issue:** File changes made through shell scripts asked the human for
  permission each time, though the session accepts edits.
  **Resolution:** File changes go through the edit tools.

- **Issue:** A constant bound to nil is gone after a resume: the dump
  holds a value as `bytes`, the envelope wire form of nil is empty, and an
  empty `bytes` field is not written.
  **Resolution:** Not part of the move, which keeps the wire form. Fixed in
  the next pull request by making the field a `cameo.Value` message, which
  has presence and the same wire form.

## Outcome
`make proto` and the envelope landed as #322, the dump as the pull request
after it. `protogen` no longer builds a descriptor for cameo's own
messages; it builds them for a script's classes only.
