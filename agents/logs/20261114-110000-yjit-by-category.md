## Objective
The README and the site are to show a table of speed: CRuby, CRuby with
YJIT and cameo, by category. Measure it.

## Progress
- [x] `compare.rb --rubies` runs a chosen set of Rubies, `yjit` among them
- [x] `categories.rb` prints a results file as a table of categories
- [x] `yjit.tsv`: all 781 cases on the three, in one run

## Obstacles
- **Issue:** The first run showed YJIT no faster than CRuby, on `fib` too.
  This shell sets `RUBYOPT=--yjit`, so the `mri` column ran with YJIT.
  **Resolution:** `mri` runs with `--disable-yjit` where the Ruby has YJIT.
- **Issue:** Timing `mri` again alone, with `--only`, made CRuby faster
  than YJIT in several categories: one Ruby timed at a time has a quieter
  machine than three had.
  **Resolution:** All three timed again in one run; the compare README
  says to do so.

## Outcomes
- Over the 772 cases all three ran: YJIT 0.88 times CRuby's time, cameo
  1.51 times. cameo is fastest on paths (0.51), strings (0.83) and times
  (0.85), and slowest on hashes (4.62) and method calls (3.28).
- A laptop, three cases at a time on 4 fast and 6 slow cores: the
  proportions hold, the digits less so. The 16-core server would be the
  better machine and costs money to rent.
