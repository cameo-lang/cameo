# Task: a proc called as a value is an activation

**Started:** 2026-11-11 21:32:00
**Ended:** 2026-11-11 21:45:00
**Strategy:** Feature (TDD)
**Status:** Completed
**Complexity:** Simple
**Used Models:** Fable 5.2
**Token usage (Estimated):** 120k input, 8k output

## Objective
`f.call(x)`, `f.(x)` and `f[x]` ran the proc through `Proc#call`, a
builtin, so in a loop of its own: a run inside a lambda paused when the
lambda returned.

## Progress
- [x] A `SEND` of `call`, `()`, `[]`, `yield` or `===` to a proc a script
      wrote pushes the block's activation
- [x] The dump holds the proc of a block's activation that was called as
      a value (`Activation.block`); one that was yielded to is still the
      block of the activation below
- [x] Tests: lambdas and procs called every way, a lambda that calls
      itself, a proc's `return` out of its method, a lambda passed with
      `&`

## Obstacles
- **Issue:** The dump of the step before had no proc for a block's
  activation: the resume took it from the frame below, which had yielded
  to it. A proc called as a value is a local, not the frame's block.
  **Resolution:** `Activation.block` holds the proc when the activation
  below did not yield to it. When it did, as in
  `def apply(&blk) = blk.call`, the resume still takes the frame's, so a
  `break` finds its call by the very same proc.

## Outcome
A script written with lambdas pauses inside them. `when ->(n) { … }` in
a `case` still calls its lambda from Go, through `===`.
