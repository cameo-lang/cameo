## Objective
`Foo.new(…)` ran a script's `initialize` through `Class#new`, a builtin,
so in a loop of its own: a run inside an `initialize` paused when `new`
returned.

## Progress
- [x] A `SEND` of `new` to a class whose `initialize` a script defined
      makes the instance and pushes the `initialize`'s activation, whose
      caller gets the instance (`machine.result`)
- [x] The dump holds the instance being filled once, in its frame
      (`Frame.building`), and refers to it from wherever it is held
      (`Binding.building`); `Activation.result`
- [x] Tests: pauses between the field assignments of an `initialize`,
      inside methods and blocks it calls, in nested `new`s

## Obstacles
- **Issue:** The instance an `initialize` fills is the one value in
  cameo that changes, and the frame's self, the frame's `Building` and
  what `new` returns are one pointer. Three copies in a dump would be
  three instances after the resume, and `self.x = …` would fill one.
  **Resolution:** The dump holds the instance in the frame, and a
  binding that is that very instance says so with the frame's index.
- **Issue:** Encoding an instance keeps its protobuf message on it, for
  the next use. On an instance still being filled that message is stale
  one assignment later, in a run that goes on after a dump failed and in
  a resumed run.
  **Resolution:** The message is dropped from the instance after the
  dump encoded it and after the resume decoded it.

## Outcome
A script that does its work in `initialize`, or under it, pauses there.
A copy of a half-made instance inside another value is a copy after the
resume; `doc/design/pause.md` says so.
