## Objective
Time code from inside a running script, so the interpreter's start is not
in the result, with the same API as Ruby so one benchmark script runs on
cameo and on CRuby.

## Progress
- [x] Expected outputs from Ruby 3.4.1 for Tms arithmetic and formatting,
  the bm, benchmark and bmbm layouts, and the errors without a block
- [x] src/stdlib/benchmark.go after benchmark 0.4.0, CPU times from
  getrusage(2)
- [x] p and puts of a Tms
- [x] Integration test, docs, make check, pull request

## Obstacles
- **Issue:** The first plan added `Process.times` and a `GC` module, which
  Ruby's pure-Ruby Benchmark uses.
  **Resolution:** Dropped on review: the Go implementation reads getrusage
  and calls runtime.GC itself.
- **Issue:** `print t` printed `Benchmark::Tms()`: ToS and Inspect dispatch
  only to methods written in cameo. Calling any builtin class's own native
  to_s recursed forever for Object.new.
  **Resolution:** A case for Tms in ToS and Inspect, as for Pathname.
- **Issue:** fine-grained async fib(29) took 8 s where fib(28) took 1.2 s:
  the live heap passes the 1 GB GOMEMLIMIT that tuneGC sets, and the
  collector runs 75 times instead of 4.
  **Resolution:** unresolved; reported, not part of this change.

## Outcome
`require "benchmark"` works as in Ruby 3.4, apart from Tms#add!, which
changes its receiver, and the address `p` of a Tms shows in Ruby.

## Insights
The 1 GB soft memory limit in src/cmd/cameo/main.go turns into a GC
death spiral once a script's live heap is larger than it.
