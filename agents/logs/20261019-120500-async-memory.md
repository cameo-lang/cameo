# Task: remove the memory pressure of fine-grained async

**Started:** 2026-10-19 12:05:00
**Ended:** 2026-10-19 13:40:00
**Strategy:** Performance
**Status:** Completed
**Complexity:** Medium
**Used Models:** Opus
**Token usage (Estimated):** 600k input, 45k output

## Objective
fib(30) fanned out with async at every level peaked at 3.4 GB and, past
the 1 GB memory limit cameo sets, spent most of its time collecting
garbage. Cut the memory, within that limit.

## Baseline (10-core M-series, fib(N) with async at every level)
- fib(29): 6.51 s, 1.77 GB; fib(30): 11.84 s, 3.44 GB
- At the peak of fib(29): 475 MB live heap, of it 340 MB promises the
  table kept for the whole run; 105,000 parked goroutines, 1.4 GB stacks.
  With GOMEMLIMIT=16GiB, 4 collections instead of 75.

## Progress
- [x] A promise ends with the method that started it, once awaited:
  fib(29) 6.51 s to 1.76 s; fib(30) unchanged, still past the limit
- [x] await runs a queued call itself; calls wait in a queue for up to
  GOMAXPROCS runners: fib(30) 14.10 s to 0.84 s, 3.38 GB to 97 MB
- [x] Full comparison on 16 cores against main and Ruby 3.4 and 4.0
- [x] make check, a pull request per change

## Obstacles
- **Issue:** The heap profile at the peak showed 196 MB in use where the
  process held gigabytes: with a high GOMEMLIMIT almost no collection ran,
  and the profile reflects the last one.
  **Resolution:** Read the live heap from GODEBUG=gctrace=1 and profiled
  under the default settings.
- **Issue:** A first step replaced the 1 GB memory limit by GOGC set from
  the live heap.
  **Resolution:** Reverted on review: cameo stays within 1 GB. With the
  queue, fine-grained async no longer comes near the limit; a script with
  more than about 1 GB live still collects most of the time (6 million
  rows: 9.9 s with the limit, 4.8 s without).
- **Issue:** With await running queued calls, RunContext returned a
  CameoError for a call the main script ran itself.
  **Resolution:** await returns ErrStopped when the run stopped during the
  call it ran.
- **Issue:** The first queue let a runner and an awaiter both unlink one
  promise.
  **Resolution:** A linked flag under the shard lock; whoever unlinks
  counts it.
- **Issue:** A test of calls that never end first polled the promise with
  resolve, which settles it.
  **Resolution:** The busy calls run for two seconds instead; the test
  checks the late call ran within one.

## Outcome
fib(30) with async: 11.84 s and 3.44 GB to 0.84 s and 97 MB, against
0.73 s sequentially. fib.rb uses N = 33: about 6.5 s in all.

Changed behaviour: awaiting a promise after the method that started it
returned and it was awaited raises "no promise N".

## Insights
A Go memory limit below what is live, stacks included, makes the
collector run continuously; it is not a cap on growth.
