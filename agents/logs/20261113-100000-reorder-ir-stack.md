## Obstacles
- **Issue:** A unit taken as the tree of an old commit took back what
  the new order had already placed below it: a test fix that had moved
  down, and later two commits that had not been placed yet.
  **Resolution:** A snapshot is allowed only when the units so far hold
  every old commit up to it, and gets the commits that moved below it
  picked on top. The rule is in stacks.md.
- **Issue:** Work logs were edited by commits far from the one that
  wrote them, so every reorder conflicted in them.
  **Resolution:** A log enters the stack once, in its final form, with
  the unit that holds the last commit to touch it.
- **Issue:** Two tests appended at the end of one file conflict when
  their commits swap.
  **Resolution:** Resolved by hand; the second of the pair is the old
  tree again.
- **Issue:** The commits of the evaluator's speed build on each other
  line by line and do not move.
  **Resolution:** They keep their order. What moved are the commits
  around them that touch other packages: values and maps before the
  flat code, the lookups by name together, the lists and walks together.

- **Issue:** One push of all 86 branches was refused by the proxy with
  HTTP 403.
  **Resolution:** Pushed in batches of ten, each atomic and with a lease
  on the commit every branch had, bottom to top. No pull request can
  close in between: one closes when its head is inside its base, and no
  new commit is inside an old one. The ten whose base would come to lie
  above them were retargeted to `main` before the first batch.

- **Issue:** After a later push of all branches the top had no run a
  minute on, and I took that for GitHub dropping the events of a push of
  many branches and pushed the stack again. The run had started two
  minutes after the push.
  **Resolution:** Wait and read the list of runs again. The rule is in
  stacks.md.
