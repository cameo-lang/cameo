## Objective
Step 23 of `doc/design/ir.md`, its third group: the methods of
Enumerable that fold a list into one value pause inside their block.

## Progress
- [x] `stdlib/folds.go`: a walk beside the definition of `inject`,
      `reduce`, `sum`, `count`, `any?`, `all?`, `none?`, `one?`,
      `take_while`, `drop_while`, `group_by`, `each_slice`, `each_cons`
      and `reverse_each`, for the calls made with a block alone
- [x] `foldsOf`: a Hash, a Set and a Range, which define some of these
      around Enumerable's, take Enumerable's steps
- [x] Tests: every pause inside these blocks lands, on a List, a Range,
      a Hash and a Set; the calls with a pattern or an operation's name
      compute what they did

## Obstacles
- **Issue:** These methods take a pattern, a symbol or a start beside
  the block, and without a block do something else again. A walk covers
  one of those forms.
  **Resolution:** The method stays as it is defined, and gets a step
  that walks when the call is the plain one and otherwise runs the
  method to its end in one step.
- **Issue:** The count showed `{a: 1}.sum { … }` and `Set[1, 2].count
  { … }` still holding a pause off: a Hash defines some twenty of
  Enumerable's methods again from their Go functions, `map` and `find`
  among them, and a Set and a Range a few, and those copies had no step.
  **Resolution:** `foldsOf` gives the copies Enumerable's steps. The
  pull request below said a Hash's `map` was a stepper through
  Enumerable; it was not until now, and its description is corrected.

## Outcome
The walks and folds a script loops with are steppers on a List, a
Range, a Hash and a Set. Left in Enumerable: the `_by` methods that sort
or compare, `uniq`, `to_h`, `to_set`, `zip`, `cycle`, `chunk_while`,
`slice_when` and the lazy enumerator.
